以下“机构”对应原图甲方，“服务方”对应乙方。分工是项目计划起点，按实际合同和授权确认；服务方协助不转移机构的医疗、安全和材料真实性责任。具体人员留待项目指定，不沿用原图姓名；受理、审核及发证主体按属地当前职责确认。

## 互联网诊疗流程（A路径的项目参考）

| 阶段 | 任务与建议分工 | 阶段完成证据及依赖 |
|---|---|---|
| 1 环境准备（5项） | ①三级等保准备与测评：机构确认主体，服务方配合；②小程序申请认证：机构；③诊疗系统部署：服务方；④HIS对接：服务方与机构信息部门；⑤公众号、商户配置：机构，按渠道及支付方案需要 | 实际部署和接口记录、适用的备案及测评材料、渠道账号状态；测评范围与项目匹配。可与材料准备并行 |
| 2 省监管平台对接（9项） | ①按实际关系签合作协议：双方；②机构及适用合作方资质：机构提供、服务方协助；③科室医师药师登记：机构；④等保材料上传：服务方协助；⑤制度准备：服务方起草、机构适配确认；⑥系统视频：服务方；⑦技术文档：服务方；⑧测试数据联调：服务方、机构配合；⑨取得审核报告：由平台相应审核方出具 | 核对当前入口及账号主体；资质、人员、合同、系统一致，联调完成并取得真实审核结果及报告。测试限允许的环境和合成数据；响应平台补正 |
| 3 行政申请（5项） | ①提交适用变更申请：机构；②审批材料：机构申报、服务方协助；③现场准备：机构、服务方提供资料；④配合适用现场检查及整改：机构主责；⑤取得许可结果：有权机关办理 | 提前取得属地指南；准备诊室、音视频设备、制度及演示证据；原图“1间诊室、2套音视频”仅是项目清单片段，按[现场审查](application-playbook.md)补齐适用项。保存受理、补正、检查和核准结果 |
| 4 上线准备（6项） | ①小程序备案及适用审核：机构；②患者小程序开发：服务方；③正式监管数据对接：服务方；④系统测试：双方验收；⑤培训：服务方组织、机构落实；⑥正式上线：机构确认条件、服务方实施 | 回传获准资质；核对许可、科目、人员、渠道审核、正式接口、测试培训、运维和应急安排后再开诊。开发和培训准备可提前进行 |

原图参考排期：环境准备约1个月、省监管对接约1自然月、行政审批时间弹性大、整体约2—3个月。仅用于说明该项目的经验估计；阶段可能交叉，也可能因测评整改、补正、审查及平台安排延长，不能直接相加或承诺拿证日期。

## 互联网医院流程（B/C路径需分别适配）

| 阶段 | 任务与建议分工 | 阶段完成证据及依赖 |
|---|---|---|
| 1 环境准备（8项） | ①公众号及商户：机构按需要；②小程序申请认证：机构；③合作协议：服务方提供草稿、实际合作双方签署；④三级等保：机构确认主体和范围、服务方配合；⑤小程序备案：机构按当前平台程序；⑥患者小程序开发上传：服务方；⑦系统部署：服务方；⑧HIS对接：服务方与机构信息部门 | 明确设立、依托与技术合作关系；系统、安全及渠道准备记录。体验版用于受控演示，不能借此提前开诊；备案在本阶段列项不意味着本阶段就能完成所有资质审核 |
| 2 省监管平台对接（7项） | ①平台注册账号：实际申请主体经办人；②主体资质提交：机构及适用设置方/合作方；③登记科室医师药师：机构；④等保与系统资料上传：服务方协助；⑤申请书、可行性报告、制度与手册：服务方起草、机构确认；⑥测试联调：服务方、机构配合；⑦取得审核报告：平台相应审核方 | 账号角色与申请路径一致，人员、系统和材料审核及联调完成；机构保持审核联系畅通。登记医师、正副高及电子病历要求按适用规则核对，不能仅按原图短句判断 |
| 3 属地行政申请（6项） | ①登记申请：机构，B适用变更、C适用执业登记；②向有权受理机关申请：机构；③提交申报材料：机构、服务方协助；④现场审查准备：机构；⑤检查及整改：机构配合、服务方提供系统演示和介绍材料；⑥许可下发：有权机关 | 属地受理清单、场所及音视频配置、PPT和系统演示、整改闭环、真实执业许可结果。原图将“审批局提交申请”标为审批局负责，执行时区分申请方提交与机关受理 |
| 4 上线准备（4项） | ①正式数据对接及资质回传：服务方、机构确认；②测试：双方；③培训：双方；④上线：机构确认条件、服务方实施 | 确认获准范围、平台数据回传及持续上报能力、患者端适用审核和验收培训后上线；费用起算按合同 |

原图将环境准备、省监管对接分别估计为约1个月，行政环节“时间弹性大”。属地咨询、系统部署、材料和上线准备可穿插推进；正式提交的先后依赖按当前办事要求确定。

## 原图备注的适用边界

这些限定随流程一起使用；不要直接转发原图作为现行审批说明。对外制作流程图时使用上面的适配内容，删去具体人员和未经核实的固定承诺。

| 原图表述 | 技能采用的处理方式 |
|---|---|
| 每月10日前提交、月底前几天测试 | 特定批次经验；与旧资料“每月25日”不同，不能任选一个当规则。按当前平台通知核实批次、截止日和测试安排 |
| 医师60岁以下、第一执业点在本机构 | 年龄限制仅为原图待核实备注；经验要求核对“独立临床经验”，注册与多机构执业要求按路径及现行依据，不把原图条件普遍化 |
| 每科一正高一副高、二级医院病历三级/三级医院四级 | 使用[路径条件](policy-and-routes.md)与[审查说明](application-playbook.md)已有适用范围及历史阶段限定，再核查当前要求 |
| 独立申请不需要合作协议 | 先区分自行建设系统和独立设置互联网医院。C路径的实体依托协议及适用技术合作协议不能因此省略；按申报材料表判断 |
| 一定选“和第三方合作”、一定用医疗机构而非公司账号 | 核实实际申请主体、角色和合作结构后选择；系统采购不自动成为共同举办医院，不能指导所有路径统一勾选 |
| 诊所备案可能免实勘、积极做主管部门工作 | 查备案诊所适用程序及正式审查要求；主管部门沟通用于咨询指南、补正和审查安排，不推导免审或例外待遇 |
| 崂山区提前部署、优先线下 | 属地项目经验，核对当前崂山指南后安排，不扩展为全省必须线下或固定程序 |
| 等保约1个月、乙方负责、甲方主体申请 | 提前核对备案及测评主体、实际系统范围和双方责任；报告、备案和部署分别查证，不保证一个月完成 |
| 微信商户必须、小程序获诊疗许可后才能备案 | 微信商户取决于支付方案；分开核对小程序备案、医疗类目资质和发布审核，原图顺序不作为平台当前规则 |
| 把用户名密码给乙方 | 不据原图要求采集或转交账号密码；由机构经办人操作，或使用平台允许的授权协作方式 |
| 拿证即上线、正式上线即计费、1次上门加多次线上培训 | 拿证后仍检查上线条件；计费起点与培训次数是具体合同约定，不默认成为全部项目承诺；原图低优先级不代表正式对接、测试、培训可省略 |

原图所列省平台与医疗机构电子化注册网址，仅作历史入口线索，不作为已核实入口推荐或要求用户在那里登录。当前入口、政策、人员条件与时限核实遵循[来源与更新](sources.md)。

## 输出项目计划

根据已知路径和进度裁剪任务，用“阶段｜任务｜主责/配合方｜前置条件｜完成证据｜当前状态｜预计时间/待核事项”组织。未知项标待确认；人员由项目指定。关键节点分别保留监管审核报告、行政许可、正式对接和上线验收，不能合并成一个“审批通过”。
