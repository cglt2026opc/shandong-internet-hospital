# 本地资料的使用与学习结论

原始资料由项目拥有者提供，历史资料根目录标识为“互联网诊疗申请”（未随仓库分发）。技能自身的科普、路径、清单与交接模板不依赖该目录继续存在。若需原始表单而目录不可访问，使用已附草稿骨架或查询当地官方表单，不假称已读原件。

完整目录清点见[local-inventory.json](local-inventory.json)，仅保存相对路径、类别、提取状态及摘要用途，不携带文件正文、患者信息或密钥。检索关键词：申请方式、国家三大文件、省监管、名称申请、线下审批、制度、合作合同。

## 已学习的内容与使用方式

| 资料组 | 提炼的知识 | 使用限制 |
|---|---|---|
| 国家三大文件、山东2023办法 | 定义、准入、责任、人员、诊疗边界、附件材料及现场审查 | 原文和后续规定优先，不套用旧程序 |
| 2025加强监管通知、数据上报整改说明 | 持续运行、处方签名、培训质控、人员数据维护 | 2025通知是依申请公开副本；内部整改说明不是政府规范 |
| 申请方式4份PDF、申请流程2份文档 | 机构/合作方、临床科室、职能部门、系统、人员、审核、联调、取报告、回传许可的数据准备顺序 | 四种历史界面选项不是四种法定登记结果；2022网址/按钮可能过期 |
| 申请注意事项 | 合同与日期、主体全称、科目二级分类、材料和系统演示一致性 | 保留可复用质量检查，排除关系免审、修改报告等不当做法 |
| 申报参阅模板、名称申请V2.0 | 申请书、可行性报告、变更表、承诺书、经办证明的字段和结构 | 先核对路径、属地正式版，不保留旧客户或地名，不预填已完成 |
| 医院管理制度、职能科室文件 | 质安、药学、病历、信息、隐私、告知、复诊风险、培训、应急、岗位 | 按医院/门诊部/诊所/服务站真实业务适配；不能有模板就判已执行 |
| 线下审批材料、系统功能清单、设备表 | 演示和证据类别，人员、系统、网络、安全、配送、保险、服务公示 | 各地差异，医保与HIS收费描述是特定项目条件 |
| 合作建设/运营合同、物流与云协议 | 责任分工、合作有效期、数据保管及退出、技术和运营边界 | 是合同样本而非合法性结论，不公开客户合同、不照搬分成/收费/期限 |
| 互联网诊疗技术手册、HIS/LIS/EMR/影像手册 | 系统支持角色、病历处方链及接口协作的准备材料 | 按目录/关键功能检索学习，不声称逐页核验所有截图或实际部署 |
| 配置表、监管字典、YPID库 | 存在账号配置、医保字段及编码版本依赖 | 仅检查表结构与前12行，不做全量药品核验；密钥不用于咨询采集 |
| 等保备案证明、完整测评报告 | 备案与测评是不同证据，须匹配实际项目 | 扫描备案证未据其作证书有效性判断；完整报告不分发，不公开内部资产细节 |

## 从历史材料中纠正的易错点

- “营业执照增加互联网诊疗”不能替代医疗机构执业许可的服务方式变更。
- “互联网诊疗和互联网医院字样不能混用”应理解为申请事项清晰，不应禁止互联网医院文稿正常描述诊疗服务。
- “每月25日、再等一个月”“合同至少两年最好三年”“微信认证300元/年”均来自历史操作经验，不当现行政策或固定费用。
- “前置审批一概不涉及”须改为按实际业务核查；不能依据旧小程序承诺书规避医疗、药品等要求。
- “CA暂用签名图片”不能推导签名图片等同有效电子签名。
- “删除审核报告小字”“关系好免实勘”不进入办理建议。只依据真实材料和依法适用程序准备。
- “是否上报备案由机构自行选择”的内部表述不能覆盖法定对接、人员备案和真实上报要求。
- 默认电子病历一级、不需证书、固定硬件与“免费HIS对接”等要结合现行标准与具体合同，不能推广。

## 读取覆盖与限制

目录中PDF、DOCX、DOC批量尝试提取正文；表格仅抽样结构。两份扫描等保备案证明未获得可用正文，未推断证书真伪/有效性；两份旧DOC手册提取为空，使用同名PDF了解目录与功能。ZIP及PNG仅清点，没有自动解包传播。见索引的状态字段。

提取是辅助阅读，不表示所有文件逐页审计完成。主要精读范围为政策、申请流程、注意事项、申报模板、监管整改、关键系统功能与制度结构；大型编码库和完整安全报告不属于基础科普所需全量知识。
