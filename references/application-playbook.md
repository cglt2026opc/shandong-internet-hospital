# 山东申报准备与整改

先用[路径参考](policy-and-routes.md)确认A/B/C/D或待核路径。下面是准备清单，不是全省统一受理目录。标注“省级规定／当地追加／项目建议”；原模板未适配时不能写成已准备完成。

两份项目流程图的分阶段任务、分工和排期边界见[四阶段流程与分工](approval-workflows.md)。需要项目计划或流程展示时按需读取。

## 从评估到上线

| 阶段 | 工作 | 完成证据 |
|---|---|---|
| 主体与路径 | 核对所在地、登记机关、资质、医师来源、合作结构和科目，提前核对属地清单 | 路径说明、现行指南、窗口核对记录 |
| 建设准备 | 约定分工，部署系统，准备人员、制度、等保与安全材料 | 真实配置、测试记录、对应安全证据 |
| 省监管对接 | 按当前接口填报机构/合作方/人员、联调数据、响应审核 | 可核验审核结果及对接报告，不只是已提交截图 |
| 行政申请 | 按属地要求申请，配合补正、适用的公示和现场审查 | 受理、整改及执业许可结果，监管报告不替代许可 |
| 上线准备 | 回传许可、配置获准科目人员、完成小程序等审核、培训演练 | 核准信息一致、验收、值班、运维安排 |
| 持续运行 | 真实上报、人员更新、质控投诉应急、年度测评及适用校验 | 运行记录、整改闭环、有效凭证 |

测试使用允许的测试环境和合成数据，不向真实业务通道上报虚假诊疗，不为活跃量补造处方。阶段可交叉推进，但未获准前不得真实开诊。

## 主要材料差异

依据SD23附件1；份数、格式、签章、入口核对属地当期清单。

| 材料 | A增加诊疗 | B第二名称 | C独立设置 |
|---|---|---|---|
| 申请表 | 变更登记申请书，写原因理由 | 变更登记申请书，写设立原因理由 | 执业登记申请书，写依托机构名称地址、拟设名称科目 |
| 省监管对接情况报告 | 有 | 有 | 有 |
| 合作协议 | 有第三方系统合作时提供 | 按共同举办及系统合作实际关系覆盖 | 设置方与实体机构合作协议；另有技术第三方时补系统合作协议 |
| 负责人及卫生技术人员名录 | 有 | 有 | 有 |
| 制度与应急预案 | 应实际落实，核对当地提交项 | 附件明确要求 | 附件明确要求 |
| 设备、系统、技术人员、三级等保证明 | 按安全规则落实，核对提交项 | 附件明确要求 | 附件明确要求 |
| 资产评估报告 | 非该路径通用项 | 非该路径通用项 | 附件明确要求；承诺容缺另查当地 |

D结合实体申请资料与附件1一（四）。经办人、真实性/信用承诺、可行性报告、图纸、保险、配送协议等按路径及当地要求加入，不说全省统一必交。济南、西海岸专用表不得直接用于其他地区。

## 材料一致性

- 主体全称、证照、印章、合同主体、签署与起止日期、系统录入相符；调整已签合同应依法修订，不改扫描件。
- 服务方式、第二名称、具体科目及二级分类、科室和人员一致。互联网医院文本可描述“互联网诊疗服务”，不机械执行两个词不得共存的旧经验。
- 医师证号、范围、地点、独立临床经验核对当前注册信息；药师有资质和真实服务关系。
- 制度适配机构实际业务，诊所不照抄不存在的住院手术业务，也不能删除必要职责掩盖缺口。
- 手册反映真实部署入口、知情同意、复诊判断、实名、电子签名、审方、病历与留痕；手册有功能不等于系统已实现。
- 功能申报与接口范围、业务一致。监管字典v2.1、YPID V9.0是库存历史版，实施时核实新版本。
- 对接报告保持原貌，不执行历史经验中删除报告文字的建议。账号、密钥及患者信息不进入公开演示或咨询卡。

## 现场审查预演

SD23附件2用于独立互联网医院和第二名称医院；A路径可参照。附件说明任一项不符合即不通过，不能用总分抵消。分清“没有证据”“已发现不符”“不适用待确认”。

| 组别 | 证据与演示 |
|---|---|
| 科目与组织 | 执业科目比对、组织架构与专人职责；独立医院不能仅挂靠实体管理部门 |
| 医护药师 | 职称执业资格、电子注册、实名、药师值班、服务关系；按适用条目核对正高副高 |
| 设施 | 至少2套服务器，应用与数据库划分；机房双路供电或应急发电；境内存储；至少2套音视频；至少两家网络商，每条带宽不低于10Mbps；云部署查实际合同和资源 |
| 系统安全 | 服务系统备案与测评、监管对接、访问控制、全程留痕、HIS/PACS或RIS/LIS交换、相应远程医疗功能演示 |
| 制度预案 | 岗位、培训考核、停电断网信息泄露预案、不良事件处置；人员能说明执行方式 |
| 诊疗流程 | 实名告知→既往资料→医师判断→病历签名处方→药师审核→后续支付/配药/流转→查询追溯；不适宜线上则终止转诊 |
| 保障 | 医责险、合作责任、投诉、数据保存能力 |

附件电子病历等级项含2022阶段目标及后续调整说明，不能把三级医院4级、二级医院3级当永久最新标准，更不能默认所有机构一级。需再查当前评价要求。

## 退回整改

根据脱敏退回意见、地区、路径、环节及材料片段，逐条输出“退回原意／材料／依据／修改动作／提供证据的人／复核点”。优先给可执行修改，不只说找壹康。

合同日期不一致→双方核对后依法修订；超科目→按真实许可调整或另办合法变更；人员不符→核实注册记录；演示入口不可用→提供受控体验授权；缺对接报告→完成要求，不制作仿件。

## 上线后

N22、SD23明确持续监管、实名、审方、留痕、安全与校验。第二名称随实体校验，独立互联网医院每年校验；年度测评和合作协议按SD23第三十八条准备。

本地SD25（2025-04-27，依申请公开副本）另列每年不少于16学时培训、每季度自查、线上备案科室每日医生上线、连续3个月无有效诊疗或数据异常超过15天的通报整改等。作为需向主管部门确认的运营线索，标清本地副本来源，不称已核验公开发布的最新政策；不把“2025年底”历史推进节点当新申报期限。

制度可按质安、实名与多机构执业、复诊转诊、处方药事、病历告知、数据权限隐私、应急、自查投诉、校验、收费公示分组。完整制度应结合真实业务编写，由机构确认负责人和生效时间。

医保、药品相关资格、小程序类目、收费项目和平台入驻另核当期要求。“系统支持医保支付”不代表任何机构自动开通医保。
